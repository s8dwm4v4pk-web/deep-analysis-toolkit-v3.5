# 分析状态 · 格式协议（隶属 SKILL v3.4.0）

> **定位**：深度分析SKILL的中间态写入/读取格式规范。共享基础设施。
> **引用方**：`SKILL.md`（v3.4.0 统一入口，所有阶段均经根 SKILL 路由至本协议）
> **存储位置**：`SKILL_ROOT/workspace/{task_name}_{YYYYMMDD}_{HHMM}/analysis-state.md`

---

## 一、文件层级

### 1.1 文件名与路径

- v3.5 起，各阶段独立写入 `analysis-state-s{N}.md`（N = 1, 2, 3, 3b, 4, 5, 6），随后由 `merge-analysis-state.py` 合并为 `analysis-state.md`（仅脚本审计存档；阶段 6 独立写 `analysis-state-s6.md` 并同步追加）
- 存储于每次任务隔离子目录：`SKILL_ROOT/workspace/{task_name}_{YYYYMMDD}_{HHMM}/`
- 路径在任务启动时确定，全流程不变
- 阶段间交接走 `s{N}-handoff.md` 摘要（`generate-handoff.mjs` 生成），下游 LLM 禁整读状态文件
- 路径通过参数显式传给所有参与方，**各参与方不自行扫描工作目录**

### 1.2 任务标识块（文件首段，必填）

```markdown
# 分析状态 · {task_id}

## 任务标识
- **task_id**: {task_name}_{YYYYMMDD}_{HHMM}
- **data_hash**: {输入数据文件的摘要哈希前8位}
- **data_path**: {原始数据文件的相对路径}
- **created_at**: {ISO8601时间戳}

---
```

### 1.3 完整性校验规则

任何参与方在读取 `analysis-state.md` 后，必须校验以下两项：
- `task_id` 与传入的参数一致
- `data_hash` 与传入的参数一致

不一致则**中断操作**，并向调用方返回校验失败原因。这是防止数据串染的第一道防线。

### 1.4 分析参数（由主 SKILL 写入，后续轮次消费）

用户在前置问答中选择的分析参数，由主 SKILL 在前置问答后写入 `analysis-state-s1.md`，并经 `s1-handoff.md` 交接给下游阶段。此后各轮次在执行收敛判断、信号筛选、图表要求时，**必须**从该章节读取参数的**实际值**来替换各自文档中的默认值。

```markdown
## 分析参数
- **P0 分析深度**: {深度分析 / 轻量分析}
- **work_dir**: {工作目录完整路径，格式: SKILL_ROOT/workspace/{task_name}_{YYYYMMDD}_{HHMM}/}
- **P1 归因收敛阈值**: {用户选择的值，如 67%}
- **P2 情景收敛门槛**: {用户选择的值，如 < 2 个}
- **P3 建议层级完整性**: {用户选择的值，如 K=3}
- **P4 筛选权重（多维信号）**: {用户选择的值，如 A×0.55 + B×0.45}
- **P5 多维可视化最低维度**: {用户选择的值，如 ≥4}
- **P6 报告格式**: {纯网页版 / A4分页版}
- **P7 图表阈值**:
  - **min-total**: {12|8|16}（图表总数下限）
  - **min-advanced**: {3|2|5}（高级图表下限）
  - **min-multi**: {1|1|2}（多维可视化下限）
- **写入时间**: {ISO8601}
```

**优先级规则**：此章节中的值为用户确认的实际参数，优先级**最高**。各消费文档中标注的"默认值"仅在用户未修改参数时生效。当 s1 状态文件（经 `s1-handoff.md` 交接）中存在「分析参数」章节时，消费侧**必须**以该章节的实际值为准，不得使用消费文档自身标注的默认值。

## 二、写入模式

### 2.1 追加模式（Append-Only，默认）

所有参与方（包括维度Agent和认知循环的各轮次）以追加模式写入，**禁止修改或删除已存在的任意章节**。

### 2.2 纠正机制

如需纠正上一轮/其他Agent的观察，不在原文上修改，而是在本轮次中新增"数据质量标注"小节：

```markdown
### 数据质量标注
- **[纠正] {章节引用}**：{原观察的准确引用}
  → {纠正后的正确表述}
  → 纠正理由：{核验依据}
```

原始观察始终保留。分析过程的痕迹本身具有价值——它让读者能看到认知是如何演化的。

### 2.3 章节标记格式

每轮次/每个Agent的写入以特定标记开头：

**认知循环模式**：
```markdown
---
## 轮次 {N}: {轮次名称}
**写入时间**: {ISO8601}
---
```

**多Agent并行模式**：
```markdown
---
## 并行维度扫描: {维度名}
**Agent**: {agent-name}
**写入时间**: {ISO8601}
---
```

### 2.4 章节隔离约定

各参与方只能写入自己负责的章节范围（由prompt中的章节标记参数明确指定）。写入时应：
1. 先检查文件中是否已存在同名章节（防止重复写入）
2. 若发现已存在 → 停止写入，返回错误
3. 若不存在 → 在文件末尾追加

## 三、各分析阶段的输出格式

### 3.1 全域扫描输出（Round 1 / 维度Agent 并行阶段）

对每个维度，以结构化信号块输出：

```markdown
### 维度: {维度名}

#### O-001: {信号简述}
- **类型**: observation | anomaly | pending
- **置信度**: high | medium | low
- **证据**: {具体的数字、比例、参照}
- **跨维验证需求**: [{维度A}, {维度B}] 或 none

#### O-002: {信号简述}
...
```

**字段说明**：
- `类型: observation` — 常规观察，无异常标记
- `类型: anomaly` — 标注为异常信号，将优先进入信号筛选
- `类型: pending` — 暂不确定，需要更多信息确认
- `置信度: high` — 数据充分支撑，可以直接使用
- `置信度: medium` — 有一定支撑力，但需交叉验证
- `置信度: low` — 数据稀疏，仅作参考
- `跨维验证需求` — 列出需要哪个维度Agent提供佐证

### 3.2 信号筛选输出（Round 2）

```markdown
### 筛选概览
- 原始信号总数: {N}
- 入选深度分析: {M}
- 筛选标准: {简述采用的标准}

---

### S-001: {信号描述}
- **优先级**: high | medium | low
- **来源维度**: [{维度A}, {维度B}]  
- **入选理由**: {为什么这个信号值得深入追查}
- **信号强度**: 多重维度证据 → {列出维度间的证据链}
- **待归因问题**: {下一轮归因时需要回答的核心问题}
- **需要的数据**: {归因分析需要但当前数据可能缺少的信息}

### S-002: {信号描述}
...
```

**优先级判定标准**：
- `high` — ≥3个维度出现呼应信号 + 与核心矛盾直接相关
- `medium` — 2个维度信号呼应，或单维度强信号
- `low` — 仅有单维度弱信号，但仍值得关注

### 3.3 深度归因输出（Round 3）

对每个入选信号构建归因分析：

```markdown
## 深度归因

### 归因: S-{编号} {信号描述}

#### 假说穷举
| 编号 | 假说 | 验证状态 | 证据 |
|------|------|---------|------|
| H1 | {假说描述} | ✅ 支持 | {具体数据支撑} |
| H2 | {假说描述} | ❌ 不支持 | {反驳数据} |
| H3 | {假说描述} | ⚠️ 存疑 | {需要哪些额外信息} |
| H4 | {假说描述} | ⚠️ 存疑 | {需要哪些额外信息} |

#### 归因链
{现象} ← {近因（直接触发因素）} ← {远因（间接促成因素）} ← {结构因（系统性根本原因）}

#### 残余未解释
{经过以上归因后仍然无法解释的部分}
- **原因**: {为什么无法解释 —— 数据不足 / 超出分析范围 / 需要外部信息}
- **重要性**: {这个未解释的部分对核心判断的影响程度: 致命 / 重大 / 次要}
```

## 四、报告生成阶段的消费规则

报告生成Agent（阶段 7a/7b）按 v3.5 交接协议只读 `s1-handoff.md`…`s6-handoff.md`（+`s3b-handoff.md`）摘要与 `blueprint.md`，**不整读** `analysis-state.md`；质量门禁脚本（assemble/verify/trace/audit）消费完整状态文件时，必须遵守以下规则：

### 消费原则

1. **仅消费"最终确认的信号"**：置信度为 high 或 medium（且经跨维验证确认）的信号
2. **不消费存疑项**：标注为 `pending`、`存疑` 或 `confidence: low` 的发现不应进入正式报告
3. **诚实标注局限性**：第3轮的"残余未解释"可选择纳入报告的"局限性声明"章节
4. **归因链选择性呈现**：核心归因链（≥1个证实+无反驳）在报告中呈现。单假说不呈现（缺乏缄默证据）
5. **章节顺序可重组**：第6轮的章节决策若合理，以此为准。否则按四层递进逻辑重组

### 引用格式

报告中的分析内容应标注引用溯源：

```markdown
{分析结论} ← [S-001, H1/H3, Round3 归因链]
```

## 五、安全性与幂等性

### 5.1 幂等写入

对同一 task_id + data_hash + 同一章节标记，最多只能写入一次。重复尝试写入时，返回错误并说明"该章节已被Agent {name}在{timestamp}写入"。

### 5.2 中断恢复

如果分析流程在中途中断（Agent异常退出），通过以下方式恢复：
1. 读取 `analysis-state-s{N}.md`（当前阶段独立文件）与 `s{N}-handoff.md` 交接摘要
2. 找到最后一个已完成的章节标记
3. 从该章节之后的下一轮次/下一步继续
4. 不需要重跑已完成的部分

### 5.3 版本标记

```markdown
## 协议版本: v1.0
## 兼容约定: 向后兼容。新增字段不破坏旧版读取逻辑。废弃字段保留至少2个大版本。
```
