# 认知循环 · 收敛与中断规则

> **使用者**：`SKILL.md`（v3.4.0 统一入口）+ 各阶段文件（每阶段必须在本文件中查找对应门禁行）
> **功能**：定义每个阶段执行前必须检查的终止条件
>
> ⚠️ **强制执行约束**（v3.4.0 起生效）：
> 1. 每个阶段在执行结束/准备进入下一阶段前，**必须**在本文件中查找对应阶段的行
> 2. **P0 为阶段 2 引擎路由的唯一权威**：路由决策的唯一来源是 `analysis-state-s1.md` 中 P0 字段字面值，不接受数据规模替代
> 3. **阶段 3b（Safety Lifecycle）已纳入决策表**：3b 不触发跳转，但在 3b 执行期间检查回归条件

## 正常收敛条件

### 条件 1：核心矛盾已充分解释

```
触发阶段：阶段 3（归因）结束后，进入阶段 4 前检查

检查项：阶段 3 输出的所有高优先级信号中，"残余未解释"的部分
是否包含标注为"对核心判断有致命/重大影响"的项目？

├─ 是 → 数据不足以确认核心矛盾 → 继续阶段 4，但要在预判中诚实标注不确定性
└─ 否 → 核心问题有充分解释 → 正常进入阶段 4
```

### 条件 2：逐阶段收敛条件（替代原统一 15% 阈值）

> **自 V2.0.1 起更新**：原 15% 边际效用阈值在不同阶段间比较不可公度的产出类型（阶段 3 归因链 vs 阶段 4 情景 vs 阶段 5 建议），统计依据不足。改为逐阶段定义专属收敛条件，阈值由用户前置参数 P1/P2/P3 决定。
> 
> **执行前读取（优先级铁律）**：每个阶段检查收敛条件前，必须先从对应阶段的 `analysis-state-s{N}.md` 的「分析参数」章节读取 P1/P2/P3 的实际值。该章节中的值为用户确认的最终参数，优先级高于下方各条件标注的默认值。默认值仅在「分析参数」章节不存在或用户未修改时生效。

#### 条件 2a：归因信度收敛（阶段 3 → 4）— 硬收敛

```
触发阶段：阶段 3（归因）结束后，进入阶段 4 前检查

检查项：阶段 3 产出中，归因信度为 low 的信号占比
        low 信号数 / 总信号数 × 100%

**执行前读取**：从 `analysis-state-s1.md` 的「分析参数」章节获取 P1 的实际值。默认 67%。
阈值校验：
├─ low 占比 > 实际 P1 值 → 数据不足以支撑情景预判和后续深度挖掘
│                        跳转阶段 7，生成"深度归因报告"（含完整假说验证但无情景预判）
└─ low 占比 ≤ P1 阈值 → 正常进入阶段 4

设计理由：若多数高优先级信号的归因都无法建立可信链条，
后续的情景推演和建议将建立在不可靠的归因基础上，属于"garbage in, garbage out"。
与其产出不可靠的预判，不如诚实地在归因层收束。
```

#### 条件 2b：情景空间覆盖度收敛（阶段 4 → 5）— 硬收敛

```
触发阶段：阶段 4（情景预判）结束后，进入阶段 5 前检查

检查项：阶段 4 产出的有意义情景数量
        情景之间有实质区分度（关键变量取值方向不同），而非仅参数微调

**执行前读取**：从 `analysis-state-s1.md` 的「分析参数」章节获取 P2 的实际值。默认 < 2 个。

当 P2 为数值阈值（< 2 或 < 3）时：
├─ 情景数 < 实际 P2 值 → 情景空间不足以支撑差异化建议
│                      跳转阶段 7，生成"归因+情景报告"（含已有情景但不做分层建议）
└─ 情景数 ≥ P2 阈值 → 正常进入阶段 5

当 P2 为「不设数量门槛」时：
├─ 检查：阶段 4「关键不确定变量」中，变量的主要走向路径（≥2 条）是否被 ≥1 个情景覆盖？
├─ 是 → 不收敛，正常进入阶段 5
└─ 否 → 关键变量走向未被情景充分覆盖，跳转阶段 7

设计理由：如果只有 1 个或没有有区分度的情景，阶段 5 的建议将缺乏
"在不同可能走向下的不同应对策略"这一核心价值，退化为一般性建议列表。
「不设数量门槛」适用于变量走向明确但情景数量天然受限的数据场景
（如仅 1 个关键变量但有 ≥2 条明确走向路径时，1 个情景覆盖一条路径即可）。
```

#### 条件 2c：建议层级完整性收敛（阶段 5 → 6）— 软收敛

```
触发阶段：阶段 5（决策建议）结束后，进入阶段 6 前检查

检查项：阶段 5 的四层建议（🔴紧急 / 🟡短期 / 🟢中长期 / 📋制度）中，
        有多少层产生了 ≥ 1 条有效建议

**执行前读取**：从 `analysis-state-s1.md` 的「分析参数」章节获取 P3 的实际值。默认 K=3。
阈值校验：
├─ 有效层数 < 实际 P3 值 → 建议覆盖不完整，但不应因此终止
│                   继续进入阶段 6，在叙事中诚实标注建议覆盖的局限性
└─ 有效层数 ≥ P3 → 正常进入阶段 6

设计理由：建议层级不完整不应截断流程——即使只有紧急+短期建议，
也比没有报告强。与 P1/P2 的硬收敛不同，此条件在未达标时"标注但不终止"，
确保分析结果总能为用户所用。
```

### 条件 3：上下文窗口逼近上限（窗口收敛）

```
触发阶段：任意阶段开始前，例行检查

当上下文窗口使用量超过 70% 时触发本条件：

检查项：
├─ 窗口使用量 ≤ 70% → 正常继续
└─ 窗口使用量 > 70% → 执行以下压缩/摘要策略：

    1. 对已完成阶段的原始输出，提取信号块和归因链摘要，
       替换冗长的全文记录，保留关键要素：
       - D 编号清单（不可压缩）
       - 信号优先级排序表（不可压缩）
       - 归因链核心路径（可压缩为摘要，保留假说→证据→结论骨架）
       - 情景空间覆盖表（可压缩为关键变量×走向矩阵）
    
    2. 压缩后，在当前阶段的 analysis-state-s{N}.md 顶部添加压缩记录：
       ```
       [WINDOW-COMPRESS] 阶段{N}前执行上下文压缩
       压缩前窗口用量: XX% → 压缩后: XX%
       压缩范围: 阶段{N-3}至阶段{N-1}原始输出摘要化
       关键数据完整性: D编号/信号表/归因骨架均已保留
       ```
    
    3. 后续阶段中，当需要引用压缩前的完整内容时，
       从对应阶段的 analysis-state-s{N}.md 的对应章节读取（磁盘存储不受窗口限制）

设计理由：全流程积累（8 个主阶段）+ vendor JS 3MB + 原始数据可能导致上下文窗口溢出。
与其在中途崩溃丢失所有状态，不如主动压缩已完成阶段的输出为摘要，
保留归因链骨架和信号表，释放窗口给后续深度分析阶段。
```

### 条件 4：达到最大阶段

```
触发阶段：阶段 7

无条件进入报告生成阶段，不执行任何跳过操作。
```

### 条件 5：分析请求已完全满足

```
触发阶段：阶段 5（建议）结束后

如果任务目标明确规定"到阶段 5 为止"，
或用户明确表示"不需要报告"，则在此终止。

否则进入阶段 6-7。
```

## 中断/跳过条件

### 中断 0：阶段 1 数据基座质量致命性缺陷

```
如果阶段 1 数据基座构建后评定为 D 级（>2 项 FAIL 或核心字段 FAIL）：

→ 不进入阶段 2
→ 产出一份"数据质量报告"，列出全部缺陷
→ 询问用户："当前数据存在 N 项致命缺陷，是否仍要继续分析？"
  ├─ 用户确认继续 → 降级为 C 级流程，报告中全程标注不确定性
  └─ 用户拒绝 → 终止，输出当前质量报告作为最终产物

A/B/C 级 → 正常进入阶段 2。C 级需在阶段 7 报告的"局限性声明"中引用阶段 1 评级。
```

### 中断 1：阶段 2 筛选结果为空中断

```
如果阶段 2 筛选后，没有任何信号符合"高优先级"标准，
并且也没有任何信号符合"中优先级"标准：

→ 有中优先级信号 → 可选进入阶段 3（分析师决策），以较低信度执行归因
→ 0 高优 + 0 中优 → 跳转阶段 7
→ 阶段 7 产出一份"数据探索报告"而非深度归因报告
→ 报告中包含：七维全域扫描结果 + 一个明确声明：
  "全维度扫描后未发现值得深度追查的信号。
   这可能意味着：(a) 数据质量不足 (b) 系统目前处于稳定均衡态 (c) 分析视角需要重新设计"
```

### 中断 2：数据质量致命性缺陷（阶段 2 兜底）

```
如果阶段 1 未触发中断，但在阶段 2 扫描中额外发现严重问题：

- 关键字段缺失率 > 50%（阶段 1 未覆盖到的字段）
- 数据行列颠倒或完全不可解析
- 数据格式与用户声明的类型完全不符

→ 跳转阶段 7
→ 产出一份"数据质量报告"，描述问题
→ 此中断作为阶段 1 门禁的冗余兜底，正常流程不应触发
```

### 中断 3：无法建立归因链

```
如果阶段 3 对某个信号穷举了全部可能假说后，
所有假说均为"存疑"或"不支持"状态：

→ 该信号降级为"当前数据无法解释"
→ 在报告中标注为"开放问题"
→ 不影响其他信号的正常分析流程
```

## 跳过规则

### 跳过 1：趋势维度不可用

```
如果原始数据没有时间维度（单期数据，无历史参照）：

→ 阶段 4（预判）中的趋势外推不可用
→ 改为基础情景罗列（列出关键变量的可能取值范围和含义，但不做时序推演）
→ 在预判章节中明确标注"数据不含时序，预判基于静态结构推断"
```

### 跳过 2：关联维度不可用

```
如果数据仅有单一数值列或行数不足（< 20）：

→ 阶段 2 中关联维度的扫描标注"数据量不足以进行可靠的相关性分析"
→ 引擎不再启动关联维度扫描，或直接跳过关联维度分析
```

> **全阶段检查**：每个阶段开始前例行检查条件 3（上下文窗口逼近上限），若触发则执行压缩策略后再进入本阶段。

## 使用方式

在各阶段执行的 prompt 中嵌入：

```
每个阶段开始前，请先读取 convergence-rules.md 并检查：
1. 是否需要跳过本阶段？
2. 是否需要终止整个循环？
3. 本阶段有任何前置条件不满足吗？

如果触发任何中断/跳过条件，请说明原因和决策，然后执行相应动作。
```
