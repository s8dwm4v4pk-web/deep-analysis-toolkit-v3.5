## Safety Lifecycle Theory 概述

Safety Lifecycle Theory 认为，任何系统的安全状态不是静态的，而是沿着可识别的阶段演化。每个阶段有其独有的特征、典型风险模式和脆弱性。准确判定系统所处的阶段，是理解风险结构、预判演化方向的前提。

### 五个演化阶段

```
阶段 0: 混沌期          阶段 1: 觉醒期          阶段 2: 建设期          阶段 3: 成熟期          阶段 4: 衰退/僵化期
┌──────────┐        ┌──────────┐        ┌──────────┐        ┌──────────┐        ┌──────────┐
│ 无体系   │ ──→   │ 问题暴露 │ ──→   │ 制度建设 │ ──→   │ 体系运转 │ ──→   │ 形式化   │
│ 无意识   │        │ 开始重视 │        │ 大量投入 │        │ 稳定改善 │        │ 边际递减 │
│ 无数据   │        │ 零散应对 │        │ 规范建立 │        │ 文化形成 │        │ 新风险   │
└──────────┘        └──────────┘        └──────────┘        └──────────┘        └──────────┘
```

| 阶段 | 核心特征 | 典型风险模式 | 阶段脆弱性 |
|------|---------|-------------|-----------|
| **阶段 0 混沌期** | 无安全管理体系、无数据收集、无风险意识 | 事故频发但无记录、问题被掩盖 | 完全缺乏数据，无法评估真实状况 |
| **阶段 1 觉醒期** | 重大事件触发关注、开始零散应对、初步数据收集 | 运动式治理、数据质量差、措施不可持续 | 重视但不持久，数据可能误导 |
| **阶段 2 建设期** | 系统性制度建设、大量资源投入、规范标准建立 | 制度与现实脱节、执行力不足、投入产出比波动 | 制度建立速度 > 文化适应速度 |
| **阶段 3 成熟期** | 体系稳定运转、持续改善机制、安全文化形成 | 边际改善递减、系统复杂性增加 | 对"黑天鹅"事件准备不足 |
| **阶段 4 衰退期** | 制度形式化、投入减少、新风险被忽视 | 老问题复发、新问题不被识别 | 数据看似正常但系统已在恶化 |

## 评估方法

### 第一步：阶段判定指标

对以下 5 个维度打分（每维 0-4 分），综合判定阶段：

#### 维度 1：制度化程度

```
0 分 — 无任何成文制度或规范
1 分 — 有零散规定但不系统
2 分 — 基本制度框架建立，但尚未覆盖全面
3 分 — 制度体系完整，定期更新
4 分 — 制度过度成熟，出现形式化迹象
```

#### 维度 2：数据质量与覆盖面

```
0 分 — 无系统数据
1 分 — 开始收集但碎片化、质量差（对应数据基座 C/D 级）
2 分 — 核心指标有数据但覆盖不全面（对应数据基座 B 级）
3 分 — 数据体系完善，质量可靠（对应数据基座 A 级）
4 分 — 数据丰富但利用率下降（出现"数据疲劳"）
```

#### 维度 3：风险响应模式

```
0 分 — 事后应对，无预案
1 分 — 事后应对为主，个别领域有预案
2 分 — 事前预防机制建立，但执行不稳定
3 分 — 预防为主，响应为辅，机制有效运转
4 分 — 过度预防，资源错配
```

#### 维度 4：改善趋势

```
0 分 — 无改善或恶化
1 分 — 个别指标改善但不稳定
2 分 — 多数指标持续改善
3 分 — 系统性改善，边际效益仍显著
4 分 — 改善趋缓，边际效益递减
```

#### 维度 5：文化成熟度

```
0 分 — 无安全文化意识
1 分 — 领导重视但基层无感
2 分 — 中层开始参与，基层逐步接受
3 分 — 全员安全意识形成，行为自觉
4 分 — 文化固化，对新兴风险缺乏敏感度
```

**综合判定**：

| 平均分范围 | 判定阶段 |
|-----------|---------|
| 0.0 - 0.8 | 阶段 0：混沌期 |
| 0.9 - 1.6 | 阶段 1：觉醒期 |
| 1.7 - 2.4 | 阶段 2：建设期 |
| 2.5 - 3.2 | 阶段 3：成熟期 |
| 3.3 - 4.0 | 阶段 4：衰退/僵化期 |

### 第二步：阶段特征验证

用阶段 3 的归因链验证阶段判定是否自洽：

- 如果判定为阶段 3（成熟期）但归因链中有多处"结构因：制度不健全"→ 矛盾，需重新评估
- 如果判定为阶段 1（觉醒期）但归因链中出现了"系统性的结构因"→ 可能阶段判定偏低
- 归因链中反复出现的模式就是当前阶段的典型风险

### 第三步：阶段脆弱性扫描

针对判定阶段，系统性地扫描该阶段的典型脆弱性：

```
当前阶段脆弱性清单：
1. {该阶段的典型脆弱性} — 当前数据中是否有表现？
   ├─ 有表现 → [证据引用自分析状态文件]
   └─ 无表现 → 标注"当前数据未观察到，但需保持警惕"
2. ...
```

### 第四步：跃迁触发条件分析

分析系统从当前阶段向前或向后跃迁需要什么条件：

```
向前跃迁（阶段 N → N+1）的触发条件：
├─ 必要条件 1: {什么必须先成立}
├─ 必要条件 2: ...
└─ 催化剂: {什么事情会加速跃迁}

向后滑落（阶段 N → N-1）的触发条件：
├─ 风险信号 1: {什么迹象说明在倒退}
├─ 风险信号 2: ...
└─ 加速器: {什么事情会导致快速滑落}
```

### 第五步：数据中的先行指标

从阶段 1 的数据形态中，识别哪些指标可以作为阶段跃迁的先行指标：

- 正向跃迁先行指标（哪些数据改善说明在向更高阶段发展）
- 反向滑落先行指标（哪些数据恶化说明在向更低阶段倒退）

## 围绕 Safety Lifecycle 的戒律

1. **阶段判定必须有多维证据支撑** — 不能仅凭两个维度打分就下结论
2. **阶段判定必须与归因链自洽** — 二者矛盾时，优先怀疑阶段判定而非归因链
3. **跃迁条件必须是具体的、可观察的** — 不能是"领导重视了就好了"这种空泛判断
4. **先行指标必须可度量** — 必须有明确的数值阈值，不能是模糊描述
5. **阶段不是"好/坏"标签** — 阶段 3 不是"好"，阶段 0 不是"坏"，每个阶段有各自的挑战
