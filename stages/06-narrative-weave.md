## 本轮职责

前5轮已经完成了全部深度分析。现在你需要把这些发现**组织成一个有说服力的叙事**。

叙事规划要回答的不是"报告该有几章"，而是"这个分析的核心故事是什么？用什么顺序讲出来最能帮助读者理解？"

## 数据质量约束

在规划叙事前，必须读取 `s1-handoff.md` 中的数据基座章节，获取 **QUALITY 评级**（A/B/C/D 级）和**勾稽校验结果**（缺失时用 `node agent-tools/scripts/state-query.mjs analysis-state-s1.md --sections=数据基座` 定向切片）。叙事语言需与数据质量匹配：

| 数据质量 | 叙事语言约束 |
|---------|------------|
| **A 级** | 可使用确定性断言（"数据显示""确认"） |
| **B 级** | 使用概率性表述（"数据表明趋势是""大概率"） |
| **C 级** | 必须使用保留性措辞（"现有数据提示""仅供参考""需进一步验证"），且在该信号对应的图表位置标注数据质量警告 |
| 有未通过勾稽项 | 涉及未通过校验项的数字时，必须注明"该数字的勾稽校验未通过，以下分析基于假设该数字可靠" |

> 数据质量评级（A/B/C/D）来自 `s1-handoff.md` 的「数据基座」章节 QUALITY 字段。本文件用"QUALITY 评级"指代该字段，避免与阶段编号混淆。

如果 C 级信号与 A/B 级信号混合在同一章节中，叙事应**显式区分信度等级**，避免读者将低信度发现误认为高信度结论。例如："以下两个趋势中，第一个有充分数据支撑（置信度高），第二个基于有限样本（仅供参考）——"

## 叙事设计方法

### 第一步：确定叙事主线

问自己：如果只能用一句话告诉读者本次分析的核心发现，那句话是什么？

这条主线必须：
- 直接回应数据系统的核心矛盾（不能是"数据总体良好"这种无信息量的）
- 有张力（如果有改善也有恶化、有进步也有风险，不要只挑一面）
- 可以从分析状态文件中直接追溯

### 第二步：确定叙事暗线

暗线是"被数据掩盖但同样重要的次要故事"。它可能是一个警示、一个被忽略的趋势、或一个值得探讨的开放问题。

### 第三步：设计章节结构

**不要照搬任何固定模板。** 章节结构应根据你的分析发现动态决定。

设计原则：
- 读者不需要先读完"背景介绍"才能看懂"核心发现"——把核心发现放在前面
- 每个章节回答一个明确的、递进的问题
- 解释性内容（归因）紧跟在描述性内容（现象）后面，不要分开放
- 建议不是报告的附录，是报告的终点——给它独立而有力的章节

### 第四步：列出图表需求

基于叙事结构，列出每个关键点需要什么样的可视化支持。**每张图表必须有明确的叙事功能，同时必须满足 P7 图表阈值硬约束。**

> **执行前必须读取**：从 `s1-handoff.md` 的「分析参数」章节获取 **P7 图表阈值** 的实际值（总计≥X / 高级≥Y / 多维≥Z），该值由用户在前置问答中选择。若 s1-handoff 缺失该字段，用 `node agent-tools/scripts/state-query.mjs analysis-state-s1.md --sections=分析参数` 定向切片回退。图表需求清单的行数不得低于此阈值——**不达标时阶段 6 必须自行重跑，不得留给阶段 7 降级处理**。

以下内容需要独立的可视化支撑（如果分析中存在）：

| 叙事要素 | 建议图表 | 数据来源 |
|---------|---------|---------|
| 核心指标 KPI | 数字卡片 / 仪表盘 | 阶段 1 D 编号 |
| 多维信号对比 | 雷达图 / 平行坐标 | 阶段 2 S-xxx |
| 假说验证总览 | 状态矩阵表 | 阶段 3 假说穷举 |
| 归因链 | 流程图 / 因果图 | 阶段 3 归因链 |
| Safety Lifecycle 阶段 | 五维雷达 / 阶段面板 | 阶段 3b 评分 |
| 情景空间 | 情景对比表 / 概率分布 | 阶段 4 情景 |
| 反事实推断 | 对比柱状图 / 决策树 | 阶段 4 反事实 |
| 建议优先级 | 优先级矩阵 / 四象限 | 阶段 5 建议框架 |

**图表数量约束（以下限值取自 s1-handoff.md「分析参数」章节的 P7 参数，在阶段 7 报告生成时强制校验）**：

| P7 级别 | 总数 ≥ | 高级图表 ≥ | 多维可视化 ≥ |
|---------|--------|-----------|------------|
| 标准（默认） | 12 | 3 | 1（维度数 ≥ P5） |
| 精简 | 8 | 2 | 1（维度数 ≥ P5） |
| 详尽 | 16 | 5 | 2（维度数 ≥ P5） |

**高级图表类型列表**：雷达图 / 桑基图 / 旭日图 / 矩形树图 / 平行坐标 / 瀑布图 / 仪表盘 / 箱线图 / 力导向图 / 哑铃图 / 日历热力图 / 散点+回归+置信带 / 棒棒糖图 / 子弹图 / 气泡图 / 象形柱图 / 折线+标注区间 / 3D散点

**图表需求清单必须使用以下结构化表格格式**（每行一张图，不得合并或省略列）：

| 图编号 | 章节 | 叙事功能（一句话） | 引擎 | 模板文件 | 数据块来源 | 是否高级 | 是否多维 |
|--------|------|------------------|------|---------|-----------|---------|---------|
| 1 | ... | ... | ECharts | radar.html | 图1数据块 | ✅ | ✅ |
| 2 | ... | ... | ... | ... | 图2数据块 | ❌ | ❌ |
| ... | ... | ... | ... | ... | ... | ... | ... |

> **模板文件名来源**：`references/methodology/visualization-mapping.md` 中列出了每种图表类型对应的模板文件完整路径（含引擎目录前缀如 `echarts/radar.html`、`d3/force-directed.html`）。填写「引擎」和「模板文件」列时必须据此文件选取——引擎不可凭空自造，模板文件路径不可省略 `{引擎}/` 前缀。

> **清单验收规则**：
> - 行数（图表总数）< P7 的总计阈值 → **阶段 6 必须自行重跑**，扩充图表需求
> - 「是否高级」列中 ✅ 计数 < P7 的高级阈值 → 重跑，补充高级图表
> - 「是否多维」列中 ✅ 计数 < P7 的多维阈值 → 重跑，补充多维图表
> - 以上三项全部达标后，方可进入第五步构建数据块

### 第四步·B：图表清单叙事质量验收（validate-chart-checklist.mjs）

> 🔴 **脚本接管**：图表需求清单写入 analysis-state-s6.md 后，必须用脚本验收 8 列结构化表格的完整性和叙事质量。LLM 不得手工检查。

```bash
node agent-tools/scripts/validate-chart-checklist.mjs "<analysis-state-s6.md 路径>" --p7-{standard|compact|exhaustive}
```

**P7 级别参数选择**：从 `s1-handoff.md` 的「分析参数」章节读取 P7 值（缺失时 `node agent-tools/scripts/state-query.mjs analysis-state-s1.md --sections=分析参数` 回退），映射为 `--p7-standard`（标准/默认）、`--p7-compact`（精简）、`--p7-exhaustive`（详尽）。

脚本验收项：
- 8 列表格完整性（每行 8 列不缺、图编号连续）
- 「引擎」和「模板文件」列有效（引擎在已知列表中，模板文件在 SKILL 包内存在）
- 图表总数 / 高级图表数 / 多维图表数 分别 ≥ P7 对应阈值（三级阈值预设已内置于脚本）
- 叙事功能列非空且 ≥ 8 字符（防止无意义占位）
- 输出 detailed pass/fail report，逐行标注违规项

> **exit ≠ 0 → HALT**，报告具体违规行和缺失字段。LLM 必须据此修正图表需求清单后重新验收，直至 exit=0。

### 第五步：构造图表数据块

> ⚠️ **关键**：阶段 7 只读 handoff 摘要，不会整读状态文件。为了图表模板的 IIFE 代码能直接复制填入、无需回溯任何章节，你仍需在此步骤中，把每张图表所需的**结构化数据数组**写入 `analysis-state-s6.md`（s6 独立状态文件），并在全部内容写完后，将 s6 章节**同步追加**至 `analysis-state.md` 完成全量存档（供质量门禁脚本审计）。

对图表需求清单中的每张图，在 `analysis-state-s6.md` 中追加以下数据块：

```markdown
#### 图{N}：{图表标题}（{图表类型}）
- 章节: {所属章节}
- 叙事功能: {这张图要说服读者什么}
- 数据类型: {从数据格式转换映射表中选对应的格式名}
- 结构化数据:
  | {x轴字段名} | {y轴字段名} | {可选: 分组字段} | {可选: 变化方向} |
  |-------------|------------|-----------------|-----------------|
  | ...         | ...        | ...             | ...             |
```

**数据完整性要求**：
- 每张图的数据必须能独立填入图表模板——R7 拿到后不需要回溯 `analysis-state-s6.md` 的任何其他章节
- 对比类图表（如柱状图对比各片区）必须同时包含所有对比对象的数值——不能只写一个"五处 5.7%"而缺失其他片区的数据
- 数值必须带单位或明确说明（%、元、人、天等），不得有裸数字
- 需要两期对比（如同比）的图表，两期数据都要列出

### 第五步·A：D 编号追溯校验（trace-d-numbers.mjs）

> 🔴 **脚本接管**：图表数据块全部写入 analysis-state-s6.md 后，必须用脚本验证所有 D-number 引用有效。LLM 不得跳过或手工执行此校验。

```bash
node agent-tools/scripts/trace-d-numbers.mjs "<analysis-state-s6.md 路径>"
```

**脚本功能**：
1. 扫描 analysis-state-s6.md 中所有 `[D0.r{C}.c{M}]` / `[D0.r{C}.col]` 格式的引用
2. 逐一验证被引用的行列坐标是否存在于 D-FOUNDATION 编号体系中
3. 输出：有效引用数 / 无效引用数 / 无效引用清单

> **exit ≠ 0 → HALT**，报告"存在 N 个无效 D 编号引用：[清单]"。LLM 必须据此修正图表数据块中的数据引用，然后重新执行校验，直至 exit=0 为止。

### 第六步：提取语言素材

从前面各阶段（阶段 1-5）的分析过程中，提取有洞察力的生动表达，集中传递给 R7。这些表达将在报告中被复用，保留分析过程的语言质感。

```markdown
### 语言素材库
| 来源 | 原文表达 | 报告用途（章节/段落） |
|------|---------|---------------------|
| 阶段3 归因 S-{编号} | "{原文中的生动表达}" | {在报告中哪里使用} |
| 阶段4 情景 {编号} | "{原文中的生动表达}" | {在报告中哪里使用} |
| 阶段5 建议 C-{编号} | "{原文中的生动表达}" | {在报告中哪里使用} |
```

**提取标准**：挑有画面感、有洞察力、在分析过程中自然浮现的表达，而不是模板化的套话。例如"机器进来了，安全意识没跟上"优于"机械化进程与安全培训之间出现结构性不匹配"。

## 章节命名原则

- 章节名应是**发现导向**的，不是**方法导向**的

```
✓ 好: "五处片区：唯一的恶化区域"
✗ 差: "区域对比分析"

✓ 好: "乡镇煤矿机电事故的深层根源"
✗ 差: "事故类型统计"
```

## 叙事完整性检查

完成后，问自己以下问题：

- [ ] 主线在报告开头就用一句话讲清楚了吗？
- [ ] 核心发现之前有没有冗余的"背景介绍"？如果有，砍掉或压缩。
- [ ] 解释（归因）紧跟在描述（现象）后面吗？还是读者需要翻好几页才能看到"为什么"？

- [ ] 建议章节之前的全部内容，能不能自然地推导出建议中的核心要点？
- [ ] 如果读者只有 3 分钟，他能通过章节名 + 每章前两段获取到 70% 的信息吗？
