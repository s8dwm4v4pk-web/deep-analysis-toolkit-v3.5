# 阶段 2-B：多 Agent 主控编排器

> **定位**：大数据集扫描的总调度中心。负责并发调度 7 个维度 Scout、收集结果、触发交叉验证、调度汇入适配。
> **前置**：阶段 1 数据基座已完成，D 编号体系和 data_hash 已写入 analysis-state-s1.md
> **工具依赖**：需要异步 sub-agent 调度能力（如 `session_spawn` 或等效并发机制）

---

## §0 文件锚定（强制执行）

> 执行 `stages/_shared-anchor.md` 定义的[标准锚定流程]：根据「阶段感知文件路由表」读取 `s1-handoff.md` 交接摘要。本文件不再重复定义锚定步骤。

---

## 编排器职责

1. **读入上下文**：从 `analysis-state-s1.md` 读取 D 编号清单、数据概况、质量评级
2. **收敛规则预检**：读取 `references/methodology/convergence-rules.md`，确认阶段 2 的各门禁条件已知
3. **并发调度**：同时启动 7 个维度 Scout（每个使用 `02-scout-template.md` 的标准提示词）
4. **超时管理**：每个 Scout 设置最大执行时间，超时结果标注 `TIMEOUT`
5. **结果收集**：等待全部 Scout 完成，汇总为统一格式
6. **触发交叉验证**：将汇总结果传递给 `02-cross-validation.md`
7. **触发汇入适配**：将交叉验证后的信号传递给 `02-merge-gate.md`

---

## 执行流程

### 第一步：准备共享上下文

从 `analysis-state-s1.md` 提取以下信息，作为每个 Scout 的共享输入：

```markdown
## 共享上下文（传递给所有 Scout）

### 数据概况
- 行数: {N}, 列数: {M}
- 列清单: {从 D0 提取}
- 时间范围: {如有}
- 数据质量评级: {A/B/C/D}
- data_hash: {8位}

### D 编号清单
{D-001 到 D-xxx 的关键数据点列表}

### 核心矛盾预判（可选）
{如果从数据概况中已经能推断出系统的核心矛盾，传递给 Scout 以聚焦扫描}

### 输出要求
每个 Scout 的输出必须遵循 `02-scout-template.md` 中定义的标准 JSON 块格式。
```

### 第二步：并发调度 7 个 Scout

对以下 7 个维度，使用 sub-agent 机制**同时**启动：

| Scout ID | 维度 | 核心问题 |
|----------|------|---------|
| SCOUT-01 | 量级维度 | 总量、集中度、头部格局 |
| SCOUT-02 | 结构维度 | 内部构成、分布形态、梯队 |
| SCOUT-03 | 趋势维度 | 方向、速度、拐点、周期 |
| SCOUT-04 | 异常维度 | 离群值、背离、突变点 |
| SCOUT-05 | 关联维度 | 变量间关系、相关性、协同变化 |
| SCOUT-06 | 对比维度 | 分组对比、目标差距、参照系 |
| SCOUT-07 | 边界维度 | 上下限、饱和度、约束条件 |

**调度参数**：
```
prompt = "读取 stages/02-scout-template.md + 共享上下文 + 维度: {维度名}"
max_turns = 5（每个 Scout 预计 3-5 轮完成分析）
timeout = 可配置（建议 120s）
```

**并发约束**：
- 所有 7 个 Scout 必须在同一时间窗口内启动
- 不得串行执行（即不能执行完 Scout 1 再启动 Scout 2）
- 如果运行环境不支持真并发，至少应描述为"逻辑并发"（所有 Scout 启动后再收集）

### 第三步：结果收集与校验

等待全部 Scout 返回结果后，执行以下校验：

```markdown
### Scout 结果收集校验
| Scout ID | 维度 | 状态 | 信号数 | 盲区数 | 备注 |
|----------|------|------|--------|--------|------|
| SCOUT-01 | 量级 | ✅/❌/⏱ | N | M | |
| ... | ... | ... | ... | ... | ... |
```

**失败处理**：
- TIMEOUT → 标注该维度未完成，后续阶段提及该维度数据缺失
- 结果格式不符合 `02-scout-template.md` 标准 → 标记为 `FORMAT_ERROR`，尝试提取可用部分
- 结果为空（0 条信号）→ 标记为 `EMPTY`，该维度在交叉验证中跳过

### 第四步：汇总聚合

将所有 Scout 的有效输出合并为一个统一的信号池，写入 `analysis-state-s2.md`：

```markdown
---
## 并行维度扫描: 汇总
**编排器**: 02-orchestrator
**写入时间**: {ISO8601}
**Scout 统计**: 7 启动 / {X} 成功 / {Y} 超时 / {Z} 错误
---

### 信号池（跨维度聚合）
{按维度分组的原始信号列表，每条标注 Scout 来源和置信度}

### 盲区总览
{所有 Scout 标注的盲区，合并去重}
```

### 第五步：触发交叉验证

将聚合后的信号池传递给 `02-cross-validation.md` 执行结构化交叉验证。

### 第六步：触发汇入适配

将交叉验证后的信号传递给 `02-merge-gate.md`，转换为 S-xxx 格式，汇入阶段 3。
